1. Dataset and Methods
1.1 Dataset & Feature Selection

The goal of this project is to design a movie recommender system that quickly adapts to the preferences of a new user. We utilize the IMDB 5000 Movie Dataset containing metadata of approximately 5000 movies. Unlike traditional collaborative filtering datasets, this does not contain prior user rating data, making content-based preference elicitation essential.

We extract a compact 89-dimensional movie representation vector x, discarding irrelevant high-cardinality features to avoid overfitting. The selected feature space is summarized below:

Feature Group Dimensions Type Description
Genres 22 Binary (One-Hot) Top 21 genres (including Western) + fallback 'other' category.
Directors 51 Binary (One-Hot) Top 50 directors by occurrence + fallback 'other' category.
Demographics & Language 2 Binary (Indicators) Indicators for USA production (country) and English language.
Content Rating 5 Binary (One-Hot) Ratings (R, PG-13, PG, G) + fallback 'other' rating.
Numerical features 6 Continuous IMDB score, duration, release year, and popularity counts.
Interactions 2 Continuous Multiplicative indicators ('indie_gem' and 'blockbuster').
Total Vector Size 88 Features (89 cols) Mixed Excludes movie_title (used as a tracking identifier only).
1.2 Preference Model & Normalization

In this study, a movie recommendation utility is modeled as U(x) = wTx, where x is a movie's feature representation vector and w is the user's latent preference vector. The objective of the preference elicitation process is to estimate w rapidly and accurately from a limited number of user interactions, such as pairwise selections (Design 1) or ranking tasks (Design 2).

To model pairwise user choices, we assume user preferences follow a Bradley-Terry model, where the probability that a user prefers movie A over movie B (written as A > B) is given by:

P(A > B) =
exp(U(xA))
exp(U(xA)) + exp(U(xB))

To ensure stable preference vector learning, features must have comparable scales. We apply:

  • Min-Max Scaling: Maps imdb_score and duration to the range [0, 1]. We also min-max scale the release year continuously, or bin it into one-hot eras (Pre-1990s, 1990s, 2000s, 2010s) to allow non-linear era modeling.
  • Log-Transformation + Scaling: Heavily right-skewed counts (num_voted_users, movie_facebook_likes, and cast_total_facebook_likes) are normalized using log(x + 1), then scaled to [0, 1].
  • Feature Interactions: To allow our linear utility function to capture non-linear preference structures, we engineered two interaction features: feature_interact_indie_gem (imdb_score * (1 - normalized_votes)) and feature_interact_blockbuster (imdb_score * normalized_votes).
  • Median Imputation: Fills missing values (108 missing years, 15 missing durations) using the dataset medians (2005.0 year, 103.0 minutes).
2. User Study
2.1 Preference Elicitation Interfaces (Design 1 & Design 2)

We designed and implemented two distinct preference elicitation interfaces to compare how user utility vectors are learned:

  • Design 1: Pairwise Selection Interface. The user is presented with 5 sequential pairs of movies (10 movies total) and selects their preferred movie in each pair. The progress is tracked via a visual progressive step counter, and the selected card highlights in green with a micro-animated checkmark.
  • Design 2: Ranking Interface. The user is presented with a single set of 10 movies and is asked to reorder them from most preferred to least preferred. We implement this using a lightweight, high-performance HTML5 drag-and-drop system. Rank badge numbers (1 to 10) adjust in real-time as elements are dragged and dropped.

To prevent learning bias, the 20 movies sampled on page load are unique and do not repeat across either interface.

2.2 User Study Design & Methodology

The objective of the user study is to compare the performance, accuracy, and user experience of these two elicitation styles:

Primary Hypothesis: Design 2 (Ranking) allows for faster and more accurate estimation of the user's preference vector w per movie shown, but incurs a higher subjective cognitive load per task than Design 1 (Pairwise).

Experimental Protocol:

  1. Task Allocation: Within-subject experimental design. Each participant performs both elicitation tasks (5 rounds of pairwise selections, and 1 round of ranking 10 items). The order of the tasks is counterbalanced to eliminate fatigue or learning biases.
  2. Evaluation & Recommendation: The elicited latent preference vector w is estimated from the user choices. A recommendation set of 10 movies is generated using the estimated utility U(x) = wTx.
  3. Feedback Phase: The recommendation set is presented to the user. The participant rates the relevance of the recommended movies. They then complete a survey based on the NASA-TLX scale to measure perceived cognitive load, effort, and frustration for each design.

Key Metrics to Compare:

  • Elicitation Efficiency: Convergence speed of w (parameterized via prediction accuracy on a hold-out validation set of movies).
  • Cognitive Load: Subjective task workload scores collected during the feedback phase.
  • Interaction Time: Total time taken by the user to complete each interface step.
