Task 1: Feature Representation

The recommendation task starts from the IMDB 5000 Movie Dataset. Since there are no explicit user ratings in this dataset, the system uses a content-based movie representation and learns user preference from elicited choices. Each movie is represented as a feature vector x, while movie_title is retained only as an identifier for displaying and matching movies.

The selected features balance predictive usefulness with interpretability. Genres, directors, language, country, content rating, release year, duration, IMDB score, and popularity counts are all meaningful to participants and can be explained in natural language when recommendations are shown.

Feature Group Encoding Human-Centric Justification
Genres Top genres one-hot encoded with an other category Genres are familiar to users and support direct recommendation explanations.
Directors Top directors one-hot encoded with an other category Director preference can strongly influence movie taste while rare directors are grouped to avoid sparse features.
Year and duration Median imputation and min-max scaling Controls for era and length preferences without letting raw scale dominate the utility model.
IMDB score and popularity counts Score scaling plus log-scaled votes and likes Captures perceived quality and popularity while reducing the effect of extreme count values.
Language, country, and rating Binary indicators These are visible constraints that can affect accessibility, familiarity, and content comfort.
Interaction features Indie gem and blockbuster indicators Allows a linear utility model to express more nuanced preferences such as high quality with low popularity.

The extraction method is implemented in project4/feature_representation.py. It computes top genres and directors, calculates normalization parameters, imputes missing year and duration values using medians, applies log transforms to skewed counts, and transforms every movie row into a consistent numeric representation.

Task 2: Extending Bradley-Terry to Rankings

For pairwise choices, the system models the probability that a participant prefers movie a over movie b with the Bradley-Terry formulation:

Pairwise model: P(a > b) = exp(U(a)) / (exp(U(a)) + exp(U(b))), where U(i) = wTxi.

A full ranking i1 > i2 > ... > in can be modeled as a sequence of choices from the remaining alternatives. This is the Plackett-Luce model, a natural listwise extension of Bradley-Terry:

Ranking model: P(i1 > ... > in) = product over k = 1 to n of exp(U(ik)) / sum over j = k to n exp(U(ij)).

This formulation is appropriate because the participant's top-ranked movie is treated as the preferred choice from all available movies, the second-ranked movie as the preferred choice among the remaining movies, and so on. It uses more information than independent pairwise choices while still relying on the same interpretable utility function U(i) = wTxi.

The prototype implements a lean approximation by decomposing each submitted ranking into all ordered winner-loser comparisons and fitting a Bradley-Terry style logistic model on movie-feature differences. This estimates w from the current session and enables the interface to show recommendations after a participant completes both elicitation designs, without requiring the class to conduct a full user study.

Task 3: User Study Design

The study compares two preference elicitation methods: pairwise selection and drag-to-rank ordering. The goal is not to run the study during the assignment, but to define a rigorous experimental protocol and provide a participant-ready interface that could be used in practice.

Research question: Does the ten-movie ranking interface produce recommendations that participants perceive as more relevant than the five pairwise choices, and what extra effort does it require?
Six-Step Study Structure Project 4 Protocol
1. Research goal and biases Compare elicitation efficiency, perceived workload, clarity, and recommendation relevance while acknowledging novelty effects, movie familiarity bias, fatigue, and order effects.
2. Study design Within-subject design: each participant completes both interfaces. Condition order is counterbalanced, with half starting pairwise and half starting ranking.
3. Materials and procedure Consent/context page, short practice explanation, five pairwise choices, one ten-movie ranking, recommendation review, separate feedback for both interfaces, and debriefing.
4. Piloting Run a pilot with 5-10 users to detect unclear wording, ranking-control problems, and timing bugs. Pilot data is excluded from the final analysis.
5. Data collection and GDPR Collect only session choices, timings, ratings, and optional comments. Do not collect names or contact details in the prototype; for a real study, provide controller contact, purpose, retention period, right to erasure, and consent withdrawal.
6. Analysis and exclusion criteria Pre-register objective exclusions: incomplete sessions, duplicate movie IDs, impossible task times, repeated non-varying choices, failed attention check, or timing more than three standard deviations from the cohort mean.
Formal hypotheses: H0: mean perceived recommendation relevance is equal for ranking and pairwise elicitation. H1: mean perceived recommendation relevance is higher for ranking than for pairwise elicitation.

The primary planned test is a paired Student's t-test on within-participant relevance-rating differences if the differences are approximately normal. If the Likert differences are clearly non-normal or strongly ordinal, the planned non-parametric alternative is a Wilcoxon signed-rank test. Secondary outcomes include task duration in seconds, number of interactions, clarity rating, perceived effort, and optional NASA-TLX inspired workload questions. If several secondary hypotheses are tested, the report should apply a Bonferroni correction to keep the family-wise error rate controlled.

Recruitment would use a convenience sample of classmates or volunteers for the course prototype, with a target of at least 10-20 participants for a small formative study and a larger sample if inferential claims are required. Participants should be adults, familiar enough with movies to make preference judgments, and informed that recommendations are exploratory estimates based only on their current-session answers.

Task 4: Participant Interface

The Project 4 page is structured as a landing page with two explicit actions: download the PDF report or start the study. The participant flow then presents a consent/context panel, the pairwise selection task, the ranking interface, a recommendation result area, and a small feedback section.

  • Pairwise interface: five movie pairs, one selected winner per pair, and progress feedback.
  • Ranking interface: ten movies reordered from most to least preferred using drag-and-drop or accessible Up and Down controls.
  • Recommendation area: receives backend recommendations with scores and short explanation tags, and can display pairwise-only, ranking-only, and combined recommendation groups if returned by the backend.
  • Timing and feedback: records per-task duration and asks separate effort and clarity questions for the pairwise and ranking designs.
  • Reset affordance: allows the participant to start over with a fresh session.
Human-Centric AI Considerations

The design follows Human-Centric AI principles by making the study purpose visible, reducing surprise about data handling, and acknowledging uncertainty. The interface states that choices are session-local, that movies are randomly sampled, and that recommendations are provisional because they are learned from limited interactions.

The model choice is also human-centered: the same linear utility model supports both elicitation methods and allows concise recommendation explanations such as genre match, director match, high IMDB score, era preference, or popularity preference.
